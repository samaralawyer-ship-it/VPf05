# Цепочка генерации модуля (VPf05)

Учебный проект по уроку **«Цепочки запросов (Chains)»**.
По короткому текстовому описанию цепочка генерирует рабочий Python-модуль,
раскладывает его по файлам и проверяет машинно — компиляцией и запуском.

## Быстрый старт

```bash
pip install -r requirements.txt
copy .env.example .env        # вписать DEEPSEEK_API_KEY

python chain.py --input examples/desc.txt
```

Результат — папка `runs/<run_id>/`. Код возврата: `0` — все проверки прошли.

## Что происходит

```
описание → [1 анализ] → [2 инструменты] → [3 реализация] → [4 проверка] → runs/<id>/
```

| Звено | Что делает | Артефакт |
|---|---|---|
| 1. Анализ | превращает описание в требования: функции, входы, выходы, ограничения, открытые вопросы | `01-analysis.json` |
| 2. Инструменты | выбирает минимальный набор библиотек и запреты | `02-tools.json` |
| 3. Реализация | пишет `main.py`, `main_test.py`, `README.md` | `03-code/` |
| 4. Проверка | `py_compile`, запуск `main_test.py`, наличие и схема `output.json` | `04-check.json`, `report.md` |

Модель вызывается через LangChain LCEL: `prompt | model | parser`.
Промпты лежат в `prompts/` и описаны карточками: роль, контекст, задача, формат.

## Почему цепочка, а не один промпт

Дробим только там, где промежуточный результат является артефактом, проверяется гейтом
или требует других параметров:

- список функций и ограничений проверяется **до** генерации кода;
- запрет `pandas` дешевле проверить на шаге 2, чем переделывать код;
- проверка вынесена в отдельный шаг, потому что это измерение, а не мнение модели.

Если бы промежуточные артефакты никто не читал, цепочку стоило бы свернуть в два шага.

## Почему проверка машинная

Просить модель найти ошибки в своём же коде — имитация проверки. Здесь проверка
не зависит от модели:

1. `python -m py_compile main.py main_test.py` — синтаксис;
2. `python main_test.py` — запуск с таймаутом 60 секунд;
3. существует `outputdata/output.json`;
4. в нём есть ключи конверта: `run_id`, `module`, `version`, `status`, `output`, `stats`.

Если проверка провалилась, звено 3 повторяется один раз с текстом ошибки в контексте.
Второй провал — статус `failed`, цепочка останавливается, отчёт сохраняется.

## Как проверить, что гейт не декоративный

Проверка повторяется без обращения к модели:

```bash
python chain.py --check-only test2
```

Чтобы убедиться, что она ловит поломку:

1. откройте `runs/<run_id>/03-code/main.py` и испортите его — например, удалите строку
   с `import json` или сломайте отступ;
2. выполните `python chain.py --check-only <run_id>`;
3. ожидаемо: `Проверка: fail`, в `04-check.json` у проверки `py_compile` статус `fail`,
   код возврата `1`.

## Артефакты прогона

```
runs/<run_id>/
├── 01-analysis.json      требования
├── 02-tools.json         выбранные библиотеки
├── 03-code/              сгенерированный модуль: main.py, main_test.py, README.md,
│                         inputdata/, outputdata/
├── 04-check.json         протокол проверок
├── report.md             сводка прогона
└── chain.log             параметры: модель, temperature, max_tokens, токены, время
```

`runs/` не коммитится: это результат прогона, а не исходники.

## Параметры

| Параметр | Значение |
|---|---|
| Модель | `deepseek-flash`, режим мышления выключен |
| `temperature` | 0.2 (звенья 1–2), 0.1 (звено 3) |
| `max_tokens` | 800 / 800 / 4000 |
| Повторы | 2 на коды 429 и 5xx, плюс повтор при ошибке разбора JSON |

Последний успешный прогон: токенов 2978 на входе и 3815 на выходе, четыре проверки `pass`,
ремонтов не потребовалось.

## Структура репозитория

```
chain.py               точка входа
prompts/               три промпта звеньев
examples/desc.txt      демонстрационное описание
ТЗ-VPf05-цепочка.md    проектная документация и обоснования
requirements.txt       зависимости
.env.example           шаблон настроек
```

## Ограничения

- генерирует только локальные модули без сети, базы данных и внешних API;
- не оценивает «красоту» кода — только работоспособность и схему результата;
- один ремонт: если модель не справилась со второго раза, прогон честно падает;
- страница урока и `runs/` в репозиторий не входят.
